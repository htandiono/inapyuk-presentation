Purwadhika final project

InapYuk

A property rental website. Guests book a stay. Owners manage the place.

Hendrik and Awan

The brief

Two roles, one website.

Guest

Search by city and date, compare the nightly price, book, pay, and review the stay.

Owner

List properties and rooms, set prices, confirm payment, and read the reports.

In the app, the owner account is called a tenant.

How we divided it

Each of us owns one feature.

Awan, Feature 1

Homepage, search, login, profiles, and the screens an owner uses to list a property.

Hendrik, Feature 2

Booking, payment proof, notifications, reviews, and the sales and occupancy reports.

We share one database and one visual style. Awan presents first. Hendrik continues from the booking calendar.

What it runs on

Website, API, and database.

  • The website is Next.js. The API is Express.
  • Data is in PostgreSQL, through Prisma.
  • The live site is inapyuk.space. The API is api.inapyuk.space.

Catalog, in code

Every list asks the database for one page.

apps/api/src/utils/pagination.ts

export function toPrismaPageArgs(input: PaginationInput): PrismaPageArgs {
  const page = Math.max(DEFAULT_PAGE, Math.trunc(input.page ?? DEFAULT_PAGE));
  const requested = Math.trunc(input.limit ?? DEFAULT_LIMIT);
  const limit = Math.min(MAX_LIMIT, Math.max(1, requested));
  return { skip: (page - 1) * limit, take: limit, page, limit };
}

Default page size is 10, and the cap is 100. Page 2 skips the first 10 rows. The browser never loads the whole table.

Accounts

Guests and owners register separately.

  • A new account gets a verification email. The link works once, then it expires.
  • Forgot password uses the same kind of one-time link.
  • Google sign-in is on the login page. It can also be linked later from the profile.

Verification email

The API waits for the mail to go out.

apps/api/src/modules/auth/auth.service.ts

const { rawToken, tokenHash, expiresAt } = createTokenData();
const { user } = await prisma.$transaction((tx) =>
  createUserAndToken(tx, newUserData(input, 'USER'), { tokenHash, expiresAt }),
);
await sendVerificationEmail(user, rawToken, 'Verifikasi Akun InapYuk');

On a hosted server the process can stop as soon as the response is sent. Waiting here means the verification mail is not dropped.

What the owner sets up

The listing is what the guest price comes from.

  • Profile: name, photo, password, and email. A new email must be verified first.
  • Property: category, photos, address, and a map pin that can be dragged.
  • Each room has free dates and a peak-season price, as a fixed amount or a percent.

Peak-season price

A percent, or a fixed amount, never below zero.

apps/api/src/services/pricing.service.ts

export function applyAdjustment(basePrice: number, type: PriceAdjustmentType, value: number) {
  const adjusted = type === 'PERCENTAGE'
    ? basePrice * (1 + value / 100)
    : basePrice + value;
  return Math.max(0, Math.round(adjusted));
}

Awan's owner screen writes this rule. Hendrik's booking reads the result for each night.

Hendrik presents Feature 2

Feature 1 already stores the nightly price. This part books the room, checks the payment, and reports the result.

Booking

The price is saved for each night.

The guest picks check-in and check-out. Nothing is charged until the booking is sent.

We store that night's price on the booking. A later change to the peak price does not rewrite an old booking.

Booking, in code

Each night is copied onto the order.

apps/api/src/modules/bookings/bookings.create.ts

function toNightCreate(night: NightlyRate) {
  return {
    date: night.date,
    basePrice: night.basePrice,
    finalPrice: night.finalPrice,
    peakSeasonRateName: night.peakSeasonRateName,
  };
}

The order keeps its own copy. Editing the room price later does not change nights that were already booked.

Order status

Five states, in order.

  1. Waiting for payment. A countdown runs until the proof is uploaded.
  2. Waiting for the owner to confirm the proof.
  3. Confirmed. The guest gets a notification and an email.
  4. Completed, after the checkout date. Only then can the guest review.
  5. Cancelled, by the guest, by the owner, or automatically if nobody pays.

Status rules

A booking can only move along these paths.

apps/api/src/modules/bookings/status-machine.ts

const TRANSITIONS = {
  WAITING_PAYMENT: ['WAITING_CONFIRMATION', 'CANCELLED'],
  WAITING_CONFIRMATION: ['PROCESSED', 'WAITING_PAYMENT'],
  PROCESSED: ['COMPLETED'],
  CANCELLED: [],
  COMPLETED: [],
};

Any other jump is rejected. A finished stay cannot go back to waiting for payment.

Payment proof

A photo of the transfer, with a size limit.

  • Jpg or png only, and no larger than 1 MB. The server checks this again.
  • If the file never arrives, the booking cancels itself and the room is free.
  • The owner sees only their own bookings, then accepts, rejects, or cancels.
  • Cancel asks for confirmation first.

File check

The server rejects the file before it is stored.

apps/api/src/middlewares/upload.middleware.ts

export const MAX_FILE_SIZE_BYTES = 1024 * 1024;
export const PAYMENT_PROOF_EXTENSIONS = ['.jpg', '.jpeg', '.png'];

export const uploadPaymentProof = buildUploader(PAYMENT_PROOF_EXTENSIONS);

1 MB is 1024 times 1024 bytes. Profile photos use the same size. Property photos allow 5 MB.

After the stay

One review, then the reports.

  • A finished stay can have one review. The owner can reply.
  • Sales can be grouped by property, by booking, or by guest, and filtered by date.
  • Occupancy is a calendar of which rooms are taken.

Reviews

One review, and only after checkout.

apps/api/src/modules/reviews/reviews.create.ts

if (booking.review) throw conflict('Pesanan ini sudah pernah diulas');
if (booking.status !== 'COMPLETED') {
  throw conflict('Ulasan hanya untuk menginap yang sudah selesai');
}

The messages say the stay was already reviewed, or it is not finished yet. The same check also refuses a review before the checkout date.

Checks we kept

What you can look for in the demo.

  • A guest cannot open another guest's booking. An owner cannot open another owner's property.
  • Forms are validated in the browser and again on the server.
  • Lists are filtered, sorted, and paged on the server.

Who can call the route

A guest route refuses an owner, and the other way around.

apps/api/src/middlewares/auth.middleware.ts

export function requireRole(...roles: UserRole[]): RequestHandler {
  return (req, _res, next) => {
    if (!req.user) throw unauthorized();
    if (!roles.includes(req.user.role)) {
      throw forbidden('Akses ditolak');
    }
    next();
  };
}

Booking routes ask for role USER. The owner's transaction routes ask for role TENANT. "Akses ditolak" means access denied.
